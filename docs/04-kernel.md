# 04 · The Linux kernel

[Docs](README.md) › **04 · Kernel**

> **In this guide:** building the kernel by hand; how a device tree is
> composed from layers and why there are 47 of them; how one DT node becomes a
> working driver; configuration fragments; and what gets installed where.

```bash
./build.sh kernel                 # config + build + install (default)
./build.sh kernel build           # just recompile (incremental)
./build.sh kernel-menuconfig      # tweak the configuration
./build.sh flash -d /dev/sdX --kernel-only   # copy the result onto an existing card
```

Source: `varigit/linux-imx`, branch `lf-6.18.y_6.18.20-2.0.0_var01`
(Linux 6.18.20 LTS plus NXP's `lf-6.18.20-2.0.0` plus Variscite's board support).

## By hand

```bash
export PATH=$PWD/build/toolchain/arm-gnu-toolchain-14.3.rel1-x86_64-aarch64-none-linux-gnu/bin:$PATH
K=build/src/linux-imx
git clone --depth 1 -b lf-6.18.y_6.18.20-2.0.0_var01 https://github.com/varigit/linux-imx.git $K

M="make -C $K -j$(nproc) ARCH=arm64 CROSS_COMPILE=aarch64-none-linux-gnu- LOCALVERSION=-custom"

$M imx8_var_defconfig                   # 1. configuration
$M Image.gz modules                     # 2. kernel + modules
$M freescale/imx8mp-var-dart-sonata.dtb # 3. device tree(s)
$M modules_install INSTALL_MOD_PATH=$PWD/out INSTALL_MOD_STRIP=1   # 4. modules -> out/lib/modules/<ver>
cp $K/arch/arm64/boot/Image.gz $K/arch/arm64/boot/dts/freescale/imx8mp-var-*.dtb out/boot/
```

| Piece | Meaning |
| --- | --- |
| `ARCH=arm64` | the 64-bit ARM architecture directory (`arch/arm64`) |
| `CROSS_COMPILE=...` | use the cross compiler instead of the PC's gcc |
| `LOCALVERSION=-custom` | appended to the version string (`6.18.20-custom`). It must be identical for the image and for `modules_install`, or modules won't load. The script passes it to every `make` call for that reason |
| `imx8_var_defconfig` | Variscite's defconfig (NXP `imx_v8_defconfig` + Variscite board drivers). **Not** `imx_v8_defconfig`, which misses parts of the board |
| `Image.gz` | gzip-compressed kernel. U-Boot's `loadimage` loads `/boot/Image.gz` and `unzip`s it |
| `INSTALL_MOD_STRIP=1` | strip debug symbols from modules (about 10x smaller) |

## Device trees

![How a device tree is built up in layers](images/dt-layers.svg)

The script builds **every** `imx8mp-var-*.dtb` listed in
`arch/arm64/boot/dts/freescale/Makefile`, currently 47. U-Boot picks the right
one at boot (see [03-uboot.md](03-uboot.md#the-boot-decision-flow)).

The names follow a pattern:

```
imx8mp-var-<module>[-1.x|-wbe]-<carrier>[-<variant>][-m7].dtb

module   : dart | som | smarc
-1.x     : module hardware revision 1.x (e.g. different Ethernet PHY supply)
-wbe     : module variant with the WBE 802.15.4 radio (SPI on ecspi1)
carrier  : sonata (DART, ex-"DT8MCustomBoard") | symphony (SOM) | echo (SMARC)
variant  : basler-isp0 / basler-isi0 / 2nd-ov5640 = camera configurations
-m7      : reserves resources for firmware on the Cortex-M7 core
```

Many of these are **composite**: the Makefile merges a base `.dtb` with
overlays (`.dtbo`) at build time, for example:

```make
imx8mp-var-dart-1.x-sonata-dtbs := imx8mp-var-dart-sonata.dtb imx8mp-var-dart-1.x.dtbo
```

To build only some of them, set `KERNEL_DTBS` in `config/local.conf`:

```bash
KERNEL_DTBS="imx8mp-var-dart-sonata.dtb imx8mp-var-dart-1.x-sonata.dtb"
```

### Your own device tree

How any node in that file becomes a running driver, step by step with the
board's real RTC:

![From one line of device tree to a working driver](images/dt-to-driver.svg)

Put `my-board.dts` (and any `.dtsi` it needs) in `custom/dts/`. The script
copies it into `arch/arm64/boot/dts/freescale/` and builds
`freescale/my-board.dtb`, so it can `#include "imx8mp-var-dart.dtsi"` like
Variscite's own files. Then tell U-Boot to use it, either with
`fdt_file=my-board.dtb` in `/boot/uEnv.txt`, or at the U-Boot prompt with
`setenv fdt_file my-board.dtb; saveenv`. See [08-customizing.md](08-customizing.md).

## Configuration changes

**Quick and local:** `./build.sh kernel-menuconfig`, then `./build.sh kernel`.
The `.config` in `build/src/linux-imx` is kept between builds.

**Reproducible (recommended):** put fragments in `config/kernel/*.cfg`:

```bash
# config/kernel/debug.cfg
CONFIG_DYNAMIC_DEBUG=y
CONFIG_USB_SERIAL_FTDI_SIO=m
# CONFIG_DRM_IMX_LCDIF is not set
```

They are merged on top of the defconfig (`scripts/kconfig/merge_config.sh`)
when the `.config` is created. After adding or editing a fragment, regenerate
the config:

```bash
FORCE_CONFIG=1 ./build.sh kernel
```

## Outputs

```
build/deploy/kernel/                 (also packed as kernel-<ver>.tar.gz)
├── boot/
│   ├── Image.gz
│   ├── config-6.18.20-custom
│   └── imx8mp-var-*.dtb             (47)
└── lib/modules/6.18.20-custom/      (modules.dep etc. generated by depmod)
```

`image.sh` unpacks this on top of the root filesystem. `flash --kernel-only`
unpacks it onto partition 1 of an existing card.

## Out-of-tree modules

```bash
make -C build/src/linux-imx ARCH=arm64 CROSS_COMPILE=aarch64-none-linux-gnu- \
     LOCALVERSION=-custom M=$PWD/my-driver modules
```
